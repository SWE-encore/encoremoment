# Encore Moment · 유튜브 탭 멀티모달 시연

서버와 PC 양쪽 체크아웃에 이 변경을 적용한다. 모델 파일은 기존 EC2 배포 경로를 사용한다.

### 노트북에서 한 번에 실행

저장소 루트에서 `bash client/tab-demo/run-live.sh`를 실행한다. 실행 중인 이전 시연이 있으면 해당 터미널에서 먼저 Ctrl+C를 누른다. 스크립트가 수정된 코드를 EC2에 보내고 SSH 터널과 로컬 페이지를 연다. `tab-v2`와 `listening on` 두 줄이 나오면 http://localhost:8000 에서 페이지를 새로고침한다. 종료 대기는 기본 3초이며, 예를 들어 5초로 시연할 때는 `ENCORE_QUIET_MS=5000 bash client/tab-demo/run-live.sh`로 실행한다.

프로젝트 EC2의 `chul` 계정 접속에서 `Permission denied (publickey)`가 반복되면 노트북에서 한 번 `bash client/tab-demo/run-live.sh --setup-ssh`를 실행한다. 출력된 `aws ec2-instance-connect` 명령은 AWS CloudShell에서 실행하고, `True`가 나오면 60초 안에 노트북 터미널로 돌아와 Enter를 누른다. 스크립트가 해당 공개키를 EC2의 `~/.ssh/authorized_keys`에 추가한다. 65초 뒤 기존 SSH 연결을 재사용하지 않고 로그인에 성공하면 시연을 시작한다. 이후에는 일반 실행 명령을 사용한다.

자동 실행은 매번 EC2의 새 시연 디렉터리에 `stream.sock`을 만들고 노트북의 8765 포트를 그 소켓에 연결한다. 기존 서버가 EC2의 8766 포트를 점유하고 있어도 자동 실행을 사용할 수 있다.

### 수동으로 EC2에서 서버 실행

저장소 루트에서 실행한다. 기존 오디오 가상환경에 YAMNet이 있고 얼굴 가상환경에 MediaPipe가 있다는 배포 기록을 전제로 한다. WebSocket과 스키마 패키지는 개인 작업 폴더에 설치한다.

```sh
MODEL_DIR=/home/ubuntu/encoremoment-models
DEMO_DEPS="$PWD/.venv-demo-deps"
"$MODEL_DIR/.venv-audio/bin/python" -m pip install --target "$DEMO_DEPS" -r server/requirements.txt
TFHUB_CACHE_DIR="$MODEL_DIR/models/tfhub" PYTHONPATH="server:$DEMO_DEPS" \
  "$MODEL_DIR/.venv-audio/bin/python" -m encore_server --model yamnet \
  --face-python "$MODEL_DIR/.venv-face/bin/python" \
  --face-task "$MODEL_DIR/models/face_landmarker.task" --port 8766
```

### PC에서 시연

첫 번째 터미널에서 SSH 터널을 유지한다. 아래 주소는 팀 접속 설정에 맞춘 예시다. SSH 키 위치가 별도로 지정된 계정은 평소 사용하는 SSH 옵션을 함께 준다.

```sh
ssh -o ExitOnForwardFailure=yes -N -L 8765:127.0.0.1:8766 chul@100.83.137.124
```

두 번째 터미널에서 저장소 루트 기준으로 실행한다.

```sh
python3 -m http.server 8000 --bind 127.0.0.1 --directory client/tab-demo
```

1. 데스크톱 Chrome에서 http://localhost:8000 을 열고 시연 시작을 누른다.
2. 영상이 열린 유튜브 탭을 선택하고 탭 오디오 공유를 켠다. 공유 중 유튜브 재생을 시작한다.
3. PC 화면의 웃음소리 점수와 같은 YAMNet 구간에 들어온 미소 점수를 확인한다. 미소는 검출된 사람별 좌우 미소 계수 평균 중 최댓값이다.
4. 웃음 장면에서 ‘녹화 신호 수신’을 확인한다. 영상이 계속 시끄러우면 공유를 유지한 채 유튜브만 일시정지한다. 마지막 반응 이후 약 3초 동안 유지 기준에 미달하면 서버가 FINAL을 보낸다. 다른 반응이 열려 있으면 그 반응까지 끝난 뒤 하나의 클립으로 저장한다.
5. OPEN 후 약 2.5초 동안 반응이 이어지면 먼저 독립적인 무음 미리보기를 재생한다. 원본 영상과 소리는 계속 녹화한다. ‘클립 저장 완료’ 뒤 플레이어가 새 클립을 자동 재생한다. 브라우저가 자동 재생을 막으면 ▶를 누른다. 기존 클립을 보는 중에도 새 클립은 목록에 추가된다. 시연을 먼저 종료하면 이미 열린 클립을 그 시점까지 저장한다. 같은 브라우저와 같은 주소에서 이후에도 클립을 재생하고 WebM을 내려받을 수 있다.

탭의 영상·소리는 브라우저 전용 파일 저장소(OPFS)에 임시 기록한다. 4초마다 독립 재생 가능한 WebM 기록을 시작하며 최근 두 기록을 보유한다. OPEN이 오면 오래된 기록을 이어서 반응 직전 장면을 포함한다. 시작 직후에는 확보한 분량만 포함하며 연속 이벤트의 사전 구간도 달라질 수 있다. 겹치는 반응은 같은 클립으로 묶는다. 테스트 페이지 `tests/playback.html`은 생성한 영상·오디오와 테스트 이벤트로 실제 녹화, 저장, 재생을 점검한다.

### 전송과 판정

탭 클라이언트는 첫 PCM 7,920샘플과 이후 7,680샘플(0.48초)마다 영상 한 장을 묶어 보낸다. 첫 두 패킷으로 15,600샘플 분석 구간을 채우고 이후 분석 창이 완성되는 즉시 전송한다. 패킷은 EMV1 4바이트, big-endian 카메라 세대(uint32), 같은 PC 단조 시계상의 영상 캡처 시각(uint64 ms), 320×180 RGB24, 기존 encore.v1 바이너리 오디오 프레임 순이다. 정상 전송 시 RGB 원시 데이터는 약 2.88 Mbps다. PCM 시작과 영상 샘플 시각을 각각 전달하며 브라우저 탭 캡처 지연은 실측되지 않았다. 오래된 카메라 세대와 중복 오디오 청크는 얼굴 추론 전에 폐기한다.

서버는 0.975초 길이의 구간을 0.48초 간격으로 분석하며 같은 구간의 미소 표본을 사용한다. 탭 시연의 웃음 시작 기준은 YAMNet 웃음 ≥ 0.25 또는 웃음 ≥ 0.10과 미소 ≥ 0.20의 동시 충족이다. 시작 후에는 각 기준의 절반(0.125 또는 0.05와 0.10)을 적용하고, 마지막으로 유지 기준을 충족한 시각에서 3초가 지나면 종료한다. 이는 시연용 초기값이다. 이벤트에는 원래 모델의 웃음 신뢰도를 기록한다. 카메라 OFF는 기존 오디오 기준을 사용한다. 비명·놀람에는 미소 조건을 적용하지 않는다. 탭 시연의 demo_scores는 각 구간의 진단 정보이고 녹화 신호는 event_update이다. 공유 입력은 영상 속 등장인물의 반응이다.

브라우저는 전체 탭에서 얼굴을 찾은 뒤, 미검출이면 화면을 여러 영역으로 나눠 원본에서 잘라 확대한다. 얼굴이 보인 영역을 유지하고 두 번 연속 놓치면 다시 탐색한다. 얼굴 분석용 미리보기에서 마지막 전송 영역을 볼 수 있다. 원본 클립은 항상 공유 탭 전체를 담는다. Chrome은 localhost와 127.0.0.1에 각기 다른 클립 목록을 보관하므로 시연할 때 같은 주소를 사용한다.
