# Encore Moment Prototype

이 시연은 PC 브라우저에서 공유한 영상과 소리로 두 모델을 시험한다. 모델 파일은 기존 EC2 배포 경로를 사용한다.

### 노트북에서 한 번에 실행

저장소 루트에서 `bash client/tab-demo/run-live.sh`를 실행한다. 실행 중인 이전 시연이 있으면 해당 터미널에서 먼저 Ctrl+C를 누른다. 스크립트가 수정된 코드를 EC2에 보내고 SSH 터널과 로컬 페이지를 연다. `rolling fusion`와 `listening on` 두 줄이 나오면 http://localhost:8000 에서 페이지를 새로고침한다. 종료 대기는 기본 3초이며, 예를 들어 5초로 시연할 때는 `ENCORE_QUIET_MS=5000 bash client/tab-demo/run-live.sh`로 실행한다.

프로젝트 EC2의 `chul` 계정 접속에서 `Permission denied (publickey)`가 반복되면 노트북에서 한 번 `bash client/tab-demo/run-live.sh --setup-ssh`를 실행한다. 출력된 `aws ec2-instance-connect` 명령은 AWS CloudShell에서 실행하고, `True`가 나오면 60초 안에 노트북 터미널로 돌아와 Enter를 누른다. 스크립트가 해당 공개키를 EC2의 `~/.ssh/authorized_keys`에 추가한다. 65초 뒤 기존 SSH 연결을 재사용하지 않고 로그인에 성공하면 시연을 시작한다. 이후에는 일반 실행 명령을 사용한다.

자동 실행은 매번 EC2의 새 시연 디렉터리에 `stream.sock`을 만들고 노트북의 8765 포트를 그 소켓에 연결한다. 기존 서버가 EC2의 8766 포트를 점유하고 있어도 자동 실행을 사용할 수 있다.

### 수동으로 EC2에서 서버 실행

저장소 루트에서 실행한다. 기존 오디오 가상환경에 YAMNet이 있고 얼굴 가상환경에 MediaPipe가 있다는 배포 기록을 전제로 한다. WebSocket과 스키마 패키지는 개인 작업 폴더에 설치한다.

```sh
MODEL_DIR=/home/ubuntu/encoremoment-models
DEMO_DEPS="$PWD/.venv-demo-deps"
"$MODEL_DIR/.venv-audio/bin/python" -m pip install --target "$DEMO_DEPS" -r server/requirements.txt
TFHUB_CACHE_DIR="$MODEL_DIR/models/tfhub" PYTHONPATH="server:$DEMO_DEPS" \
  "$MODEL_DIR/.venv-audio/bin/python" -m encore_server --model yamnet \
  --face-python "$MODEL_DIR/.venv-face/bin/python" \
  --face-task "$MODEL_DIR/models/face_landmarker.task" --port 8766
```

### PC에서 시연

첫 번째 터미널에서 SSH 터널을 유지한다. 아래 주소는 팀 접속 설정에 맞춘 예시다. SSH 키 위치가 별도로 지정된 계정은 평소 사용하는 SSH 옵션을 함께 준다.

```sh
ssh -o ExitOnForwardFailure=yes -N -L 8765:127.0.0.1:8766 chul@100.83.137.124
```

두 번째 터미널에서 저장소 루트 기준으로 실행한다.

```sh
python3 -m http.server 8000 --bind 127.0.0.1 --directory client/tab-demo
```

1. 데스크톱 Chrome에서 http://localhost:8000 을 열고 **Start session**을 누른다.
2. 영상이 열린 유튜브 탭을 선택하고 탭 오디오 공유를 켠다. 공유 중 유튜브 재생을 시작한다.
3. PC 화면의 웃음소리 점수와 같은 YAMNet 구간에 들어온 미소 점수를 확인한다. 미소는 검출된 사람별 좌우 미소 계수 평균 중 최댓값이다.
4. 웃음 장면에서 **Recording signal received**과 촬영 시점부터 신호 수신까지의 시간을 확인한다. 3초간 반응이 잦아들면 서버가 FINAL을 보낸다. 첫 트리거 전 15초와 후 10초가 기본 재생 구간이다. 종료 시점 이내의 고유 재감지는 5초씩 연장하며, 최대 60초에 도달한 뒤의 다음 재감지는 연결된 다음 클립을 연다.
5. 공유를 유지하면 클립의 뒤쪽 여유분까지 확보한 후 WebM이 저장된다. 화면에서 기본 구간을 재생하거나 편집 여유분이 담긴 전체 파일을 내려받을 수 있다. 공유를 먼저 종료하면 저장 전 영상은 삭제된다. 같은 브라우저와 주소에서 저장한 클립을 다시 열 수 있다.

브라우저는 OPFS에 약 5초 단위로 독립적인 WebM 파일을 닫는다. 이벤트가 없는 동안 기본 보존 시간은 30초다. 여기에는 사전 15초, 편집 여유 5초, 신호 전달 지연 여유 10초가 포함된다. 이 두 여유 시간은 시연용 초기값이다. 여러 이벤트가 같은 조각을 사용하면 모든 해당 클립이 끝날 때까지 보존한다. 브라우저 스케줄링에 따라 조각 길이가 달라질 수 있다. 저장 시 오디오·비디오 트랙 번호를 맞추고 클러스터 시간을 촬영 시계에 맞춰 한 WebM으로 조립한다. 편집 여유를 포함한 조각 전체를 저장하며 기본 재생 구간과 누락 범위는 옆의 JSON에 기록한다. 해상도·코덱 등 형식이 바뀌면 그 지점에서 파일을 나눈다. 같은 이벤트의 파일은 목록과 다운로드 파일명에 `file-1-of-2`처럼 순서가 표시된다.

저장소 루트에서 `node --test client/tab-demo/tests/*.test.mjs`로 구간 선택·중복·취소를 검사한다. GStreamer가 설치된 환경에서는 WebM 조립 후 두 트랙의 디코딩도 검사한다. 같은 로컬 서버의 `/tests/playback.html`에서 합성 영상과 소리로 실제 브라우저 저장과 구간 경계를 넘는 재생을 확인할 수 있다.

### 전송과 판정

탭 클라이언트는 첫 PCM 7,920샘플과 이후 7,680샘플(0.48초)마다 영상 한 장을 묶어 보낸다. 첫 두 패킷으로 15,600샘플 분석 구간을 채우고 이후 분석 창이 완성되는 즉시 전송한다. 패킷은 EMV1 4바이트, big-endian 카메라 세대(uint32), 같은 PC 단조 시계상의 영상 캡처 시각(uint64 ms), 320×180 RGB24, 기존 encore.v1 바이너리 오디오 프레임 순이다. 정상 전송 시 RGB 원시 데이터는 약 2.88 Mbps다. PCM 시작과 영상 샘플 시각을 각각 전달하며 브라우저 탭 캡처 지연은 실측되지 않았다. 오래된 카메라 세대와 중복 오디오 청크는 얼굴 추론 전에 폐기한다.

서버는 길이 0.975초인 YAMNet 창을 0.48초마다 평가한다. 얼굴 결과는 같은 PC 촬영 시각을 기준으로 겹치지 않는 0.48초 구간에 한 번만 배정한다. 프레임별로 가장 큰 사람의 미소 점수를 구하고, 한 구간에 여러 프레임이 있으면 중앙값을 쓴다. 얼굴이 늦거나 없어도 웃음소리 0.25 이상이면 즉시 OPEN이 가능하다. 약한 소리에는 해당 얼굴 작업을 최대 80ms 기다린다.

누적 경로에서 소리 A와 미소 V의 기본 참조값은 0.10, 0.20이다. 둘 다 참조값의 절반 이상인 구간에서만 `0.48 × (min(A/0.10, 1) + min(V/0.20, 1)) / 2`를 더한다. 매번 최근 5초만 남기고 현재 구간도 기여했을 때 누적 1.44점·초 이상이면 트리거한다. 참조값을 모두 충족한 세 구간 또는 두 값이 절반인 여섯 구간이 이에 해당한다. 유지 기준과 조용한 시간 3초는 별도로 적용한다. 비명·놀람은 기존 클래스별 오디오 기준을 따른다. `demo_scores`는 진단용이고 `event_update`가 PC에 전달하는 녹화 신호다. 화면에 표시되는 얼굴 처리 시간에는 공유 얼굴 워커 대기가 포함될 수 있다.

브라우저는 전체 탭에서 얼굴을 찾은 뒤, 미검출이면 화면을 여러 영역으로 나눠 원본에서 잘라 확대한다. 얼굴이 보인 영역을 유지하고 두 번 연속 놓치면 다시 탐색한다. 얼굴 분석용 미리보기에서 마지막 전송 영역을 볼 수 있다. 원본 클립은 항상 공유 탭 전체를 담는다. Chrome은 localhost와 127.0.0.1에 각기 다른 클립 목록을 보관하므로 시연할 때 같은 주소를 사용한다.
